# 算力助手与一键对照评测

## 用户流程

目标用户：科研/课程小组需要批量筛查图片，希望复用团队已有 GPU，并得到可下载的检测结果。主线工作负载为 YOLO11n 批量目标检测。

1. 用户自己的 Agent 通过 `cef dataset add <目录> --name <名字>` 登记数据。网页不上传、删除或管理数据集。
2. 网页「算力助手」新建团队共享会话，选择已有数据集，描述处理目标。会话可重命名、搜索、归档、恢复及加载更早历史。
3. 默认自动使用兼容设备，也可手动选定机器。确认卡列出实际数据来源与所选设备数量，点击后创建任务。选中的设备离线时等待恢复，不会静默转给其他机器。
4. 从任务详情查看每台设备的贡献，展开推理输出查看原图上的检测框和置信度，下载 JSON/结果 ZIP。
5. 「性能评测」选相同数据集和至少两台 GPU，点击一次即可自动执行完整对照，结果保存在服务端，支持查看阶段任务、取消和导出 JSON。

所有会话为团队共享，Token 持有者均能访问；本次不引入个人账号。原来的 `pool` 对话原样保留为「团队历史对话」。任务与来源会话/预览关联，服务端对同一预览的重复确认返回同一 Job ID。

## 一键对照的真实步骤

- 准备：固定输入清单及 SHA256、参数、模型哈希和设备配置，拒绝重复输入文件。所选设备必须在线、空闲、声明 CUDA，持有相同的标准模型。
- 临时保留这些设备给本次评测，普通 CEF 作业等待；不能隔离机器上其他软件的负载，设备所有者应关闭竞争负载。
- CPU 参考阶段：第一台选中机器实际用 CPU 计算全部输入，不计入性能成绩；结果必须回报 CPUExecutionProvider。
- 每轮轮换单机与多机条件的顺序；每个条件先用至多四张图片预热，不计入成绩，然后处理同一完整输入集。每台机器的 slots/max_batch 保持相同，池条件总并发是参与设备槽位之和。
- 正式输出必须回报 CUDAExecutionProvider，并与 CPU 参考作一对一类别、框坐标（0.5px）和置信度（0.003）比对。空检测也是合法模型结果；这是数值一致性验证，不是标注数据集上的准确率证明。
- 一个最终逻辑任务只计一次。任何缺失/错误输出使本次实验失效，不发布 η/S。资源缺失保留空值，不填 0。
- 取消会取消未完成的阶段并释放设备；Coordinator 重启将运行中的评测标记 interrupted，不暗中续跑并混合时间窗。

计时口径：Coordinator 创建 Job 至最终结果回传完成，包含排队、Worker 下载输入和上传输出，排除 CPU 参考、预热及事后校验。输入为已登记数据集，不含用户初次登记上传，也不含客户端下载结果包。

每条件多轮吞吐取中位数，再计算 `η = Ppool / ΣPi × 100%`、`S = Ppool / max(Pi)`。它们不等于 GPU 理论 FLOPS 利用率。

这是**有限批次的服务吞吐**。窗口不足 30 秒或资源采样不足五点会明确提示未证明稳定饱和；η>100% 提示复核。正式比赛应先预跑增加真实、不同的图片数量，确认持续有排队工作、窗口足够且没有外部竞争负载，再复测全部条件。不能靠等待、重复无用途输入或修改分母提升成绩。

报告保留全部参与设备（包括贡献为零者）、逐阶段 Job ID、各设备有效贡献、重试次数、原始心跳采样和时间窗、模型/输入指纹、槽位和最大领取批次。多机正式阶段任一选中设备贡献为零时实验不成立，应增加负载后重测。

## Worker 升级要求

CPU 参考和显式 CUDA 模式是新能力。两台 Worker 必须同步这次代码后重启。Windows 专用 GPU 启动器 `deploy/gpu_worker.py` 已兼容 CPU 参考；普通 Worker 适配器也增加 `device=auto|cpu|cuda`，显式模式拒绝悄悄回退。

旧 Worker 可能忽略 device 字段，此时参考阶段输出仍为 CUDA，系统会明确失败，不能据此宣称评测完成。无需因此开放远程 Shell 或新增公网端口。

## 五分钟演示建议

- 0:00–0:40：说明课程/科研图片筛查需求，展示通过本地 Agent 登记的全新输入。
- 0:40–1:10：新建会话，选择数据集与两台机器，确认检测任务。
- 1:10–2:20：观察任务分发和两台机器实际贡献。输入规模根据赛前预跑校准，不加人为等待。
- 2:20–3:10：查看检测框、数值结果并下载。
- 3:10–4:20：打开提前完成的正式单机/多机对照，解释 η/S、资源利用率和至少一个可验证的瓶颈。
- 4:20–5:00：说明用户价值与成本/替代方案。商业化同学补充硬件、电费、带宽、稳定性、授权及推广假设。

缩略图仍通过 API/CLI 可用，适合作为接入和正确性冒烟，网页不再放置四大块演示预设。

## 本轮验证与边界

- 新版前端回归：15 项，包含无网页文件控件、会话上下文和选机任务提交。
- 新增后端测试：会话隔离/归档、预览幂等、设备 allowlist、评测保留设备、取消与重启恢复、完整阶段编排、错误结果不得生成指标。完整编排测试使用明确标记的模拟 Worker 输出，不能作为 GPU 成绩。
- 本机 RTX 5060 实际运行同一张公开 bus 图片：CPU 与 CUDA 各检测到五个目标，并通过上述数值容差。此项验证新版启动器的两种引擎路径，不是双 GPU 吞吐测试。
- 已在真实浏览器检查共享会话新建、重命名、数据集引用、聊天主体布局和评测入口。
- 尚需在两台独立物理 GPU 电脑升级后跑正式对照，校准负载规模和持续时间；补充实际设备型号/内存/网络、所有者授权、版本、现场断线反馈及商业化材料，才能宣称整个比赛要求已闭环。
